# **Experimental Framework and Repository Organization**

## **1. Dataset Organization and Loading**

The experiments use two dataset configurations: **Minimal** and **Normalized**. Each configuration contains four CSV files corresponding to the experimental partitions:

| File                | Purpose                                 |
| ------------------- | --------------------------------------- |
| `train.csv`         | Model training                          |
| `eval.csv`          | Validation and hyperparameter selection |
| `test.csv`          | Final in-dataset evaluation             |
| `cross_dataset.csv` | Cross-dataset generalization evaluation |

Each CSV follows the same structure:

| Column    | Description                                       |
| --------- | ------------------------------------------------- |
| `text`    | Processed textual content                         |
| `year`    | Publication year, when available                  |
| `AI`      | Indicator of whether the text was generated by AI |
| `dataset` | Name of the source dataset                        |
| `label`   | Target class for fake-news classification         |

The datasets are organized as follows:

```
Datasets/
├── minimal/
│   ├── train.csv
│   ├── eval.csv
│   ├── test.csv
│   └── cross_dataset.csv
└── normalized/
    ├── train.csv
    ├── eval.csv
    ├── test.csv
    └── cross_dataset.csv
```

Both configurations are loaded independently for model training and evaluation. The same partition definitions are maintained across model architectures to support comparisons between preprocessing strategies.

### **2.1. Model Experiment Organization**

Each model is evaluated under two configurations:

- **Non-optimized:** Uses the predefined baseline hyperparameters.
- **Optimized:** Uses hyperparameter optimization to identify a configuration that improves validation performance.

Each experiment contains:

- `Notebook.ipynb`: Model implementation, training, validation, and evaluation.
- `Results/`: Model-specific outputs, including evaluation metrics and other relevant experimental artifacts.

The same organization is maintained for both Minimal and Normalized datasets.

### **2.2. Consolidated Results**

The root-level `Results/` directory contains the consolidated experimental analysis.

`Results.ipynb` collects and compares the outputs generated by the individual model experiments, considering:

- Model architecture.
- Preprocessing configuration (Minimal or Normalized).
- Optimization status (Non-optimized or Optimized).
- Evaluation partition (in-dataset or cross-dataset).

The directory also stores comparison figures and summary tables to facilitate the analysis of model performance across experimental configurations.

## 3. Hyperparameter Configuration and Multi-Objective Optimization

Each model is evaluated under two experimental configurations:

- **Non-optimized:** Uses predefined baseline hyperparameters to establish a reference performance.
- **Optimized:** Applies the Non-dominated Sorting Genetic Algorithm II (NSGA-II) to explore the hyperparameter search space through multi-objective optimization.

### 3.1. Optimization Objectives

The optimization process considers two competing objectives:

1. **Maximize F1-score:** Improve classification performance.
2. **Minimize inference time (ms/sample):** Reduce the computational cost of making individual predictions.

The optimization problem can be expressed as:

\[
\max_{\theta} F1(\theta)
\]

\[
\min_{\theta} T_{\mathrm{inference}}(\theta)
\]

where \(\theta\) represents a candidate hyperparameter configuration.

Because these objectives may conflict, the optimization process seeks a set of non-dominated solutions rather than a single solution that optimizes both objectives simultaneously.

### 3.2. NSGA-II Optimization

NSGA-II is employed to explore the hyperparameter search spaces and identify Pareto-optimal configurations.

The algorithm evaluates candidate configurations according to their classification performance and inference time. Through non-dominated sorting and diversity preservation, it progressively identifies solutions that represent different trade-offs between the two objectives.

The resulting Pareto front contains configurations for which no alternative solution provides both a higher F1-score and a lower inference time.

### 3.3. Pareto Solution Selection

After optimization, the Pareto-optimal solutions are evaluated using Euclidean distance to identify a representative configuration.

Since the objectives have different units and scales, their values must first be normalized. The selection process considers the ideal point, representing the maximum F1-score and minimum inference time.

The selected configuration is the Pareto solution with the shortest Euclidean distance to this ideal point:

\[
d_i =
\sqrt{
(1-\widehat{F1}_i)^2+
\widehat{T}_{i}^{\,2}
}
\]

where:

- \(\widehat{F1}_i\) is the normalized F1-score of solution \(i\).
- \(\widehat{T}_i\) is its normalized inference time.
- \(d_i\) is the Euclidean distance to the ideal point.

The selected solution represents a compromise between classification performance and computational efficiency.

### 3.4. Experimental Comparison

The non-optimized and optimized configurations are compared to assess the impact of multi-objective hyperparameter optimization.

The comparison considers:

- F1-score improvement.
- Inference-time reduction.
- Trade-offs between predictive performance and computational efficiency.
- Changes in the selected hyperparameter configurations.

The same optimization objectives and Pareto-based selection strategy are applied across all model architectures and preprocessing configurations to maintain a consistent experimental framework.
